# 插件配置

本章讲解 `${entry}_config.lua`（插件配置文件）的写法与保留字段。

## 两个 config 的区别

插件目录下有两个名字里带 `config` 的文件，职责完全不同：

| 文件 | 位置 | 职责 | 谁来改 |
|------|------|------|--------|
| `config.lua` | 插件根目录 | 插件元数据：名称、版本、作者、分类等 | 插件作者，玩家不改 |
| `${entry}_config.lua` | 插件根目录 | 插件参数：玩家可调的数值、开关 | 玩家在插件管理器中改 |

- 元数据字段见 [插件开发文档](/wiki/plugin_guide) 的「插件元数据文件」一节。
- 配置文件是**可选**的：没有 `${entry}_config.lua` 时，插件管理器中不会出现「配置」按钮。
- 文件名必须是 `${entry}_config.lua`（`${entry}` 换成你自己的 entry），否则本体识别不到。

## 基本格式

配置文件就是一个返回 table 的 Lua 文件：

```lua
-- ${entry}_config.lua
return {
	-- 可调参数：数字、布尔值、字符串、扁平数组
	attack_cooldown = 1,
	use_damage_true = false,
	damage_type = "physical",
	attack_damages = {
		50,
		100,
		150,
	},

	-- 保留字段：字段名 → 显示名称
	key_label_map = {
		attack_cooldown = "普攻冷却时间(秒，0.1-5)",
		use_damage_true = "造成真实伤害",
		damage_type = "伤害类型",
		attack_damages = "普攻各级伤害",
	},

	-- 保留字段：显示顺序（可选）
	key_order_list = {
		"attack_cooldown",
		"attack_damages",
		"damage_type",
		"use_damage_true",
	},
}
```

参数支持下列类型：

| 类型 | 编辑器表现 | 示例 |
|------|-----------|------|
| `number` | 数值输入 | `attack_cooldown = 1` |
| `boolean` | 开关 | `use_damage_true = false` |
| `string` | 文本输入 | `damage_type = "physical"` |
| 扁平数组 | 每项一行的输入列表 | `attack_damages = { 50, 100, 150 }` |

数组请写成**连续的一维数组**，元素使用数字、布尔值或字符串；嵌套 table 不是受支持的写法，本体不会把它当作可编辑项来渲染。

## 保留字段

下面三个字段名是本体**保留**的，它们只用来描述配置，本身不会出现在配置面板里，也不会被当作插件参数读取：

- `key_label_map`（**必需**）：字段名到显示名称的映射。
  **没有在这里登记的字段不会出现在配置面板中**，玩家也就改不到它。因此每加一个可调参数，都要同步补一条标签。
  建议把取值范围直接写进标签文本，例如 `attack_cooldown = "普攻冷却时间(秒，0.1-5)"`，玩家就不必去翻文档。

- `key_order_list`（可选）：字符串数组，按数组顺序自上而下显示配置项。
  省略时，本体按标签文本排序；写了 `key_order_list` 就以它为准，没被列进去的参数不会显示（即使已在 `key_label_map` 中登记）。
  参数不多时可以省略，让本体自动排序。

- `__default_config`（**保留，不要手写**）：本体在首次读取配置时自动写入的「默认值快照」。
  插件管理器靠它区分「玩家改过的值」和「作者写的默认值」，从而在插件更新时决定哪些值该保留、哪些该跟随新版本。手写它会让更新合并逻辑判断错误，请交给本体维护。

## 在插件中读取配置

配置文件位于插件根目录，由于 `plugins/?.lua` 在 require 路径中，使用 `${entry}.` 前缀引入即可：

```lua
local config = require("${entry}.${entry}_config")

function hook:init(mod_data)
	self.attack_cooldown = config.attack_cooldown
end
```

`${entry}.` 前缀是必须的：插件目录下独有的文件在 `require` 时都要加这个前缀，否则不同插件里的同名文件会互相冲突。

## 更新时的合并规则

玩家改过配置后，插件更新**不会**把玩家的设置冲掉：

- 插件新版本自带的 `${entry}_config.lua` 会与玩家本地配置合并。
- 玩家改过的字段保留玩家的值。
- 玩家没改过（仍等于旧默认值）的字段，采用新版本的默认值。
- 玩家本地新增、而新版本没有的字段保留。
- 新版本新增的字段直接补进来。
- 判断「玩家有没有改过」依赖 `__default_config`；老插件没有这个记录时，本体退化为「保留本地值、只补新增字段」。

## 约定与注意事项

- 配置文件里**只放玩家该调的东西**。层级门槛、特例名单、尺寸上限这类实现常量，放在插件模块顶部，不要让玩家来背。
- 字段名用 `snake_case`，并与 `key_label_map` 一一对应；成对的键不要漏写标签，漏了参数就直接不显示。
- 同一个字段的类型发生变化时（例如从数字改成数组），旧值会被新默认值替换。
- 配置的修改只有在插件管理器里点「应用」时才会写盘；点了「应用」后本体还会调用插件的 `on_config_change`，详见 [🔥 热重载](/wiki/plugin_guide/hot_reload)。
